### B 的备注

**B10 的成本要说清楚。** Windows 上做全用户态 TUN 需要引入 netstack（gvisor）数千行依赖，加 wintun.dll、管理员权限、路由表修改。这不是"补一个模块"，是开新战场。SOCKS5 已经覆盖了接管能力，TUN 的收益主要在"体验无缝"，不在"能力更强"。**除非演示脚本明确需要，否则不做。**

**B11 现在是 B 最该做的事。** Phase 2 验收标准是「断一 IP 后新连接自动避开」，目前只有单元测试覆盖了调度器单点行为，没有覆盖整条链路。

**B12 有个原则性矛盾需要解决**：状态接口刻意做成只读（能改状态的本地接口等于开后门），但演示需要故障注入。可行的折中是加一个只在 `--debug-control` 启动参数下挂载的路由，默认不启用。这个取舍由你定，定了记到 `docs/adr/`。
